**Goal:** Physics problems authored as *scenes* (bodies, phases, events, a sought) that compile into system-template documents consumed unchanged by the existing engine — recovering multi-phase problems (exam-audit #31 class) and re-deriving pursuit from a scene.

**Architecture:** A pure compiler layer `templates/scenes/` (ontology → principle KB → compiler) emits the exact JSON-shaped dict that `templates.declarative.parse_template` already accepts (variables + `auxiliary` + equations + constraints + default_split + golden_cases). The engine, contract, harness, and five-stage gate are **not modified** — a compiled scene passes through the same `validate_template` gate as any hand-written system template. This is milestone 1 of the Andes-lite direction (see the Andes deep-dive memo): authored scenes now; scene *sampling* is a later milestone.

**Tech Stack:** Python 3.13 (`.venv` in the main checkout), SymPy (indirectly — the compiler emits equation *strings*; only the existing parser sympifies them), pytest.

## The scene document format (fixed by this plan)

```json
{
  "topic": "two-phase-ascent",
  "bodies": [
    {
      "name": "rocket",
      "phases": [
        {"kind": "constant-acceleration", "u": 0, "a": "a", "duration": "t1"},
        {"kind": "constant-acceleration", "u": "auto", "a": "neg:g",
         "duration": "auto", "end_condition": {"v": 0}}
      ]
    }
  ],
  "given": {
    "a":  {"unit": "m/s^2", "ranges": {"easy": [2, 10, false], "medium": [2, 15, false], "hard": [2, 20, false]}},
    "t1": {"unit": "s",     "ranges": {"easy": [2, 10, false], "medium": [2, 15, false], "hard": [2, 20, false]}},
    "g":  {"unit": "m/s^2", "ranges": {"easy": [10, 10, false], "medium": [10, 10, false], "hard": [10, 10, false]}}
  },
  "sought": {"quantity": "total_displacement", "body": "rocket", "name": "H",
             "unit": "m", "ranges": {"easy": [1, 2000, false], "medium": [1, 4000, false], "hard": [1, 8000, false]}},
  "events": [],
  "constraints": [],
  "golden_cases": [
    {"given": {"a": 8, "t1": 10, "g": 10}, "difficulty": "easy", "expected": "720"}
  ],
  "trust_state": "unverified"
}
```

Field semantics (v1, closed set — reject anything else loudly):
- `phases[].kind`: `"constant-velocity"` (field `v`) or `"constant-acceleration"` (fields `u`, `a`).
- Phase field values: a given name (string), a number (pinned exact value, emitted inline into the equation), `"auto"` (chain from the previous phase: for `u`, use the previous phase's end velocity — error if phase 1), or `"neg:NAME"` (the negation of a given — for decelerations like gravity).
- `duration`: a given name, or `"auto"` → the duration becomes an auxiliary `t_<i>`; a phase with `"auto"` duration MUST have an `end_condition` or be closed by a `meet` event (else underdetermined — compiler error).
- `end_condition`: `{"v": <number>}` — the body's end velocity in this phase equals the number (e.g. 0 at the top of ascent).
- `events`: v1 supports one kind — `{"kind": "meet", "bodies": ["A", "B"], "head_start": {"body": "B", "given": "gap"}, "at_end_of_phase": 1}`: both bodies' positions are equal at the end of the named phase index, with body B starting `gap` ahead. Emits auxiliary `x_meet` and two position equations.
- `sought.quantity`: `"total_displacement"` (sum of a body's phase displacements), `"duration_of_phase"` (with `"phase": i` — that phase's duration must be `"auto"`), or `"given"`-style direct quantity (`"phase_field"`, with `"phase": i, "field": "a"|"v"|"u"` — the named given becomes the find instead of a given). Closed set; reject others.
- `constraints`: passed through to the compiled doc (same DSL), PLUS the compiler always adds `t_i > 0` for auto durations and `x_meet > 0` when a meet event exists.

## Quantity naming (Task 1 fixes this; every later task relies on it)

| Quantity | Name | Unit | Role |
|---|---|---|---|
| duration of phase i (auto) | `t_<i>` | s | auxiliary |
| displacement of body b in phase i | `s_<body>_<i>` | m | auxiliary (always emitted per phase) |
| end velocity of body b in phase i | `vend_<body>_<i>` | m/s | auxiliary (emitted only when needed: accel phases that chain, or with an end_condition) |
| meet position | `x_meet` | m | auxiliary |
| sought | its `name` from the scene | its `unit` | find (a declared variable) |

## Equations emitted per phase (the principle KB, Task 2)

- constant-velocity, duration D, speed V: `Eq(s_b_i, V*D)`; if `vend` needed: `Eq(vend_b_i, V)`
- constant-acceleration, duration D, initial U, accel A: `Eq(s_b_i, U*D + A*D**2/2)`; if `vend` needed: `Eq(vend_b_i, U + A*D)`
- `end_condition {"v": k}`: `Eq(vend_b_i, k)` (forces `vend` emission)
- chaining (`"u": "auto"`): U of phase i is the *symbol string* `vend_b_(i-1)` (forces `vend` emission in phase i−1)
- `"neg:g"` renders as `(-g)` in the equation string
- meet event at end of phase 1: `Eq(x_meet, s_A_1)` and `Eq(x_meet, gap + s_B_1)` (generalized: sums of phase displacements up to that phase; v1 only requires `at_end_of_phase: 1` for two-body scenes — reject deeper meets loudly, noted as v2)
- total_displacement sought H over n phases: `Eq(H, s_b_1 + s_b_2 + ... + s_b_n)`

Worked determinism example (two-phase-ascent): unknowns = find `H` + auxiliaries `{s_rocket_1, vend_rocket_1, s_rocket_2, vend_rocket_2, t_2}` = 6; equations = s1, vend1, s2, vend2, end-condition, H-sum = 6. ✓ Golden: a=8, t1=10, g=10 → vend1=80, s1=400, t2=8, s2=320, H=720.

### Task 3: The compiler

**Files:** Create `templates/scenes/compile.py`; export `compile_scene` and `SceneError` from `templates/scenes/__init__.py`; Test `tests/test_scene_compiler.py` (append).

**Produces:** `compile_scene(scene: dict) -> dict` returning a template doc (the exact shape `parse_template` accepts). Algorithm:
1. Validate top-level keys (closed set), body names unique, phase kinds known, all referenced given names declared, sought name not colliding with a given/auxiliary.
2. Walk each body's phases in order resolving `u: "auto"` chains (forcing `needs_vend` on the previous phase), `duration: "auto"` → auxiliary `t_<i>` (shared across bodies at the same index; v1: multi-body scenes must have equal phase counts of 1 — reject multi-phase multi-body loudly as v2), `end_condition` → equation + forces vend.
3. Process `events` (meet → `x_meet` aux + two equations; validate head_start given exists).
4. Process `sought` per its kind; `total_displacement` → sum equation; `duration_of_phase` → the find IS `t_<i>`, so that auxiliary becomes a variable instead (name it by `sought.name`, substituting the name into all emitted equations — implement by emitting with the sought name directly, not post-hoc string replacement); `phase_field` → the named given moves from `given` to the find slot.
5. Assemble: `variables` = remaining givens + find (each with unit+ranges), `auxiliary` = collected aux dict, `equations`, `root_policy` = `{"name": "smallest_positive_physical"}`, `constraints` = scene constraints + auto `t_<i> > 0` + `x_meet > 0` when present, `default_split` = all givens → find, `golden_cases` = scene golden cases with `"find": sought.name` injected, `topic`, `trust_state`.
6. **Determinism check** (Andes' well-posedness contract, pre-gate): `len(equations) == 1 (find) + len(auxiliary)` must hold — else raise `SceneError("scene is underdetermined/overdetermined: N equations for M unknowns")`.
